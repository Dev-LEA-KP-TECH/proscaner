## หน้าจอและฟีเจอร์

แท็บล่าง 5 แท็บ: **หน้าหลัก · วินิจฉัย · ค่าสด · โรงรถ · ตั้งค่า**

- **รู้จักรถอัตโนมัติ** — ต่อตัวสแกนแล้วแอปอ่าน VIN ถอดเป็นยี่ห้อ (กว่า 100 รหัสผู้ผลิต) ปี (เมื่อ VIN ระบุได้) และเชื้อเพลิง
  แล้วจับคู่/สร้างรถในโรงรถให้เอง รุ่นรถเลือกครั้งเดียวด้วยการแตะ (มีรายการรุ่นยอดนิยมในไทย) แอปจะจำและใช้กับรถรุ่นเดียวกันคันอื่นอัตโนมัติ
  รถที่ไม่ส่ง VIN เลือกรถจากโรงรถครั้งเดียว ผลสแกนและเลขไมล์จะบันทึกเข้ารถคันนั้น
- **หน้าหลัก** — การ์ดรถ (คะแนนสุขภาพ เลขไมล์) ปุ่มสแกนด่วน/สแกนทั้งคัน แจ้งเตือนถึงกำหนดบำรุงรักษา และตารางเครื่องมือ
- **วินิจฉัย** — สแกนด่วน (กล่องเครื่องยนต์) หรือสแกนทั้งคัน (ค้นหากล่อง ABS ถุงลม เกียร์ ฯลฯ ด้วย UDS/KWP บน CAN)
  ผลเป็นภาษาไทยพร้อมสาเหตุ/วิธีตรวจ ความพร้อมตรวจสภาพ Freeze Frame รายงาน PDF และลบรหัส (รวมกล่องอื่นได้)
- **ค่าสด** — เกจ (เจ้าของรถ) หรือรายการตามกลุ่ม (ช่าง) กราฟเต็มจอ บันทึกการขับ แดชบอร์ด
- **โรงรถ** — รถหลายคัน ข้อมูลลูกค้า ประวัติเลขไมล์ กำหนดบำรุงรักษา รหัสหัวฉีด (สแกน QR) ประวัติการสแกนรายคัน
- **ตั้งค่า** — โหมด ธีม 6 สี หน่วย ข้อมูลอู่+โลโก้สำหรับ PDF เกณฑ์แจ้งเตือน ข้อมูลตัวสแกน สำรอง/กู้คืนข้อมูล บันทึกการสื่อสาร

เครื่องมือ: เช็คเลขไมล์จริง · ตรวจรถมือสอง · แดชบอร์ดขับรถ (จอนอน ไม่ดับ ทริป/สิ้นเปลือง) · เช็คแบตเตอรี่ 4 ขั้นตอน ·
บันทึกการขับ (CSV, เทียบก่อน-หลัง) · จับเวลา 0–60/0–100/60–100/402 ม. · ข้อมูลรถ/VIN/Calibration ID/CVN ·
ประวัติ · กล่องทั้งหมด + อ่าน DID (ช่าง) · ทดสอบก่อน/หลังรีแมพ (ช่าง) · Mode 06 misfire รายสูบ (ช่าง) · ค้นหารหัส 614 รหัส · เทอร์มินัล (ช่าง)

## เช็คเลขไมล์จริง ทำงานอย่างไร

เทียบหลายแหล่งที่ปลอมพร้อมกันยาก: เลขไมล์หน้าปัด (ผู้ใช้กรอก) กับ
1. เลขไมล์ที่กล่อง ECU เก็บ (PID A6 — รถรุ่นใหม่ส่วนใหญ่ปี 2019+)
2. ชั่วโมงเครื่องสะสม (PID 7F) → ความเร็วเฉลี่ยตลอดอายุ ควรอยู่ราว 16–80 กม./ชม.
3. จำนวนครั้งที่สตาร์ท (Mode 09 IUPR) → กม. ต่อการสตาร์ท ควรอยู่ราว 4–60 กม.
4. ปีรุ่นจาก VIN → กม./ปี
5. ประวัติที่เคยบันทึกในโรงรถ → เลขไมล์ต้องไม่ลดลง

ผลเป็น **หลักฐานประกอบ ไม่ใช่ข้อพิสูจน์** รถที่ไม่ส่งค่าเหล่านี้จะได้ผล "ข้อมูลไม่พอจะสรุป"
บางยี่ห้อเก็บเลขไมล์สำรองในกล่องอื่นด้วยรูปแบบเฉพาะ ซึ่งต้องใช้เครื่องมือของยี่ห้อนั้น

## ขอบเขตของ ELM327 (บอกตรงๆ)

ทำได้: OBD-II ทุกโหมดมาตรฐาน (01 02 03 04 06 07 09 0A), อ่าน/ลบรหัสกล่องอื่นแบบ UDS/KWP บน CAN, อ่าน DID
ทำไม่ได้: เขียนข้อมูลลงกล่อง (เข้ารหัสหัวฉีด, รีเซ็ตเลขไมล์, จูน), คำสั่งที่ต้อง Security Access ของแต่ละยี่ห้อ,
ข้อความยาวหลายเฟรมขาออก (ต้องใช้ตัวสแกนชิป STN) — แอปจึงเก็บรหัสหัวฉีดไว้อ้างอิงเท่านั้น

## ความปลอดภัย: ด่านอ่านอย่างเดียว (v0.6.1)

ทุกคำสั่งที่ออกจากแอปผ่านจุดตรวจเดียว (`core/safety/command_guard.dart` เรียกจาก `Elm327._transmit`) จึงไม่มีทางหลุดจากหน้าใดหน้าหนึ่ง

- **ส่งได้**: คำสั่งอ่านค่า OBD-II (01 02 03 05 06 07 09 0A), KWP2000 (12 13 17 18 1A 21), UDS (19 22),
  3E (บอกกล่องว่ายังต่ออยู่) และ 10 01 / 10 81 (กลับโหมดปกติ ใช้ตอนค้นหากล่อง) กับคำสั่งตั้งค่าตัวสแกน (AT/ST)
- **ไม่ส่งเลย**: รีเซ็ตกล่อง (11), เข้าโหมดพิเศษ (10 xx อื่น), ปลดล็อก (27), เขียนข้อมูล (2E 3B 3D), สั่งอุปกรณ์ทำงาน (2F 30 08),
  โปรแกรมพิเศษ (31 32 33 38 39), แฟลช (34–37), ปิดการสื่อสาร/การบันทึกรหัส (28 85) และคำสั่งที่ไม่รู้จัก
  รวมถึงคำสั่งตัวสแกนที่ทำให้ตัวสแกนส่งข้อความเองถึงรถ (ATWM, STPX, ATFCSD ที่ไม่ใช่แบบมาตรฐาน) และ ATCAF0
- **ลบรหัส** (04 / 14): ส่งได้เฉพาะจากปุ่ม "ลบรหัส" ที่มีหน้าต่างยืนยัน (หน้าวินิจฉัยและหน้ากล่อง) ผ่าน `Elm327.allowClearing`
- **ชุดค่า**: ตอนนำเข้า (JSON หรือ CSV แบบ Torque) บรรทัดที่ใช้คำสั่งต้องห้ามจะถูกข้าม แอปขึ้นรายการว่าข้ามบรรทัดไหน เพราะอะไร
  หน้าแก้ไขค่าบันทึกคำสั่งต้องห้ามไม่ได้ ชุดที่เก็บไว้แล้ว ("ชุดของฉัน") ไม่ถูกลบหรือแก้ แค่ค่าที่ใช้คำสั่งต้องห้ามจะขึ้นว่า "ไม่ส่ง"
  และหน้าทดสอบรีแมพจะไม่เลือกค่าเหล่านั้นมาอ่านระหว่างขับ
- **เทอร์มินัล**: พิมพ์ได้เฉพาะคำสั่งอ่านค่า และคำสั่งตัวสแกนที่ดูข้อมูลอย่างเดียว (ATI AT@1 ATRV ATDP ATDPN ATCS ATIGN ฯลฯ)

- **ห้ามเก็บกุญแจและรหัสผ่านไว้ในคอมเครื่องนี้** (เครื่องมีไวรัสที่คอยกลับมาติดตัวคอมไพล์) ไฟล์กุญแจและรหัสผ่านเก็บแยกกันอย่างน้อย 2 ที่
  ถ้ากุญแจหาย แอปที่ลงไว้จะอัปเดตทับไม่ได้ ถ้ากุญแจรั่ว คนอื่นทำแอปปลอมที่อัปเดตทับได้
- **เซ็นบนคลาวด์ (วิธีที่ใช้อยู่)**: รัน `BUILD_RELEASE.bat` ได้ `release\for_signing\ProScaner-<เวอร์ชัน>-for-signing.apk` (ลงเครื่องไม่ได้จนกว่าจะเซ็น)
  แล้วให้ Claude เซ็นด้วย `apksigner` บนคลาวด์ (ส่งไฟล์กุญแจกับรหัสผ่านในแชต) Claude ตรวจชื่อแพ็กเกจและตรวจว่าไม่มีไฟล์โปรแกรม Windows
  แปลกปลอมใน APK ก่อนเซ็น แล้วส่งไฟล์ที่เซ็นแล้วกลับมาเป็นชิ้นๆ ให้ `JOIN_RELEASE.bat` ต่อและตรวจ SHA-256
  - v0.6.2 เซ็นด้วย `tool\cloud_signing\v2sign.py` บนคลาวด์ (APK Signature Scheme v2 ด้วยไลบรารี `cryptography` ไม่ต้องดาวน์โหลด apksigner)
    สคริปต์นี้ไม่มีกุญแจหรือรหัสผ่านอยู่ข้างใน: `info` ตรวจลายนิ้วมือกุญแจ, `sign` เซ็น, `verify` ตรวจลายเซ็นและ digest
    (ทดสอบกับลายเซ็นที่ apksig ของ Google สร้างแล้วตรงกัน และแท็บเล็ตรับอัปเดตทับ 0.6.1 ได้ 27 ต.ค. 17:23)
  - ตั้งแต่ v0.6.5 ใช้ APK ที่ GitHub Actions build จากเครื่องสะอาด (`test.yml` งาน Android) แทนไฟล์จากคอมเครื่องนี้:
    repo เป็น public จึงไม่เก็บ APK เป็น Artifact แต่เข้ารหัส (AES-256 + `tool/cloud_signing/transfer_pub.pem`) ไว้ใน branch `android-apk`
    พร้อม `INFO.txt` (commit, ขนาด, SHA-256) ถอดได้เฉพาะ Claude บนคลาวด์ แล้วเซ็นด้วย `v2sign.py` เหมือนเดิม
- **เซ็นบนคอมที่สะอาดหรือระบบสร้างแอปบนคลาวด์ (เช่น GitHub Actions)**: ตั้งตัวแปร `PROSCANER_RELEASE=1` และให้ Gradle รู้ที่อยู่กุญแจ
  ผ่าน `android/key.properties` (`storeFile`, `storePassword`, `keyAlias`, `keyPassword`) หรือตัวแปร `PROSCANER_KEYSTORE`,
  `PROSCANER_KEYSTORE_PASSWORD`, `PROSCANER_KEY_ALIAS`, `PROSCANER_KEY_PASSWORD` แล้วสั่ง `flutter build apk --release`
  (`key.properties`, `*.jks` อยู่ใน .gitignore แล้ว)
- **ขึ้น Play Store**: ใช้ `flutter build appbundle` แบบเดียวกัน และเปิด Play App Signing (Google เก็บกุญแจหลัก ถ้ากุญแจฝั่งเราหาย/รั่วขอเปลี่ยนได้)
- **ย้าย "ชุดของฉัน" จากตัวทดสอบไปแอปตัวจริง**: ในตัวทดสอบ เปิดค่าเฉพาะยี่ห้อ > เมนูของชุด > คัดลอก แล้วในแอปตัวจริง กดนำเข้า > วางจากคลิปบอร์ด
  (ทำทีละชุด ตัวทดสอบยังอยู่และข้อมูลไม่หาย) ตั้งแต่ v0.6.2 ย้ายทุกอย่างทีเดียวได้ด้วย สำรอง/กู้คืนข้อมูล (หัวข้อถัดไป)

## สำรอง/กู้คืนข้อมูล และบันทึกการสื่อสาร (v0.6.2)

อยู่ที่ ตั้งค่า > ข้อมูลและบันทึก

- **สำรองข้อมูล**: รถในโรงรถ (ข้อมูลลูกค้า เลขไมล์ บำรุงรักษา รหัสหัวฉีด) ประวัติสแกน "ชุดของฉัน" ข้อมูลอู่+โลโก้ ค่าตั้งค่า
  บันทึกการขับ และผลทดสอบรีแมพ รวมเป็นไฟล์ JSON ไฟล์เดียว (`ProScaner_backup_<วันเวลา>.json`)
  - **บันทึกไฟล์สำรองลงเครื่อง**: เลือกที่เก็บเอง (เช่น Download) ผ่านหน้าต่างเลือกไฟล์ของ Android ไม่ต้องขอสิทธิ์ที่เก็บข้อมูล
  - **ส่งไฟล์สำรอง**: ส่งทาง LINE / Drive / อีเมล
- **กู้คืน**: เลือกไฟล์ แอปบอกก่อนว่าในไฟล์มีอะไร แล้ว**รวม**เข้ากับข้อมูลในเครื่อง ไม่ลบของเดิม
  - รถคันเดียวกัน (VIN ตรงกัน หรือ id ตรงกันและ VIN ไม่ขัดกัน) เติมเฉพาะช่องที่ยังว่าง และรวมประวัติเลขไมล์ รหัสหัวฉีด รายการบำรุงรักษา
  - ค่าที่ตั้งไว้แล้วไม่เปลี่ยน ชุดค่าที่มีอยู่แล้วไม่เพิ่มซ้ำ (ดูจาก id, ชุดจากคลังเดียวกัน หรือเนื้อหาเดียวกัน)
  - ชุดค่าในไฟล์ถูกตรวจแบบเดียวกับการนำเข้าชุดค่า: คำสั่งที่ไม่ใช่การอ่านค่าไม่ถูกนำเข้า
  - กู้ซ้ำกี่ครั้งก็ไม่ซ้ำ และก่อนกู้คืนแอปเก็บสำเนาข้อมูลเดิมไว้ในแอป (`backups/before_restore_*.json` 3 ไฟล์ล่าสุด)
- **ย้ายจากตัวทดสอบไปแอปตัวจริง**: ในตัวทดสอบกด "บันทึกไฟล์สำรองลงเครื่อง" (เก็บใน Download) แล้วในแอปตัวจริงกด "กู้คืนจากไฟล์สำรอง" เลือกไฟล์นั้น
- ไฟล์สำรองมีข้อมูลลูกค้า (ชื่อ เบอร์โทร ทะเบียน VIN) ส่งให้เฉพาะคนที่ไว้ใจ
- **บันทึกการสื่อสาร**: ทุกครั้งที่เชื่อมต่อตัวสแกนกับรถจริง แอปเก็บทุกคำสั่งที่ส่ง ทุกคำตอบ พร้อมเวลา (มิลลิวินาที) ข้อผิดพลาด
  และเหตุที่การเชื่อมต่อจบ (ตัดเอง หลุด เชื่อมต่อไม่สำเร็จ) เป็นไฟล์ข้อความ 1 ไฟล์ต่อการเชื่อมต่อ 1 ครั้ง
  (`comm_logs/` เก็บ 30 ครั้งล่าสุด รวมไม่เกิน 50 MB) หัวไฟล์มีรุ่นแอป ชนิดการเชื่อมต่อ และระบบของเครื่อง
  - ดูในแอป ส่งให้ผู้พัฒนาทาง LINE ปิดการบันทึกได้ ลบทั้งหมดได้ โหมดทดลองไม่บันทึก
  - ใช้ตอนลองกับรถจริงแล้วค่าแปลก อ่านค่าไม่ได้ หรือเชื่อมต่อไม่ได้ (ไฟล์มี VIN ของรถ)

  (ใส่ตัวเชื่อมคำที่มองไม่เห็นภายในคำ และจุดตัดที่มองไม่เห็นหน้า/หลังคำ ตัวอักษรที่เห็นเหมือนเดิม) ใช้กับการแสดงผลเท่านั้น

## ค่าเฉพาะยี่ห้อ

ค่าที่ OBD มาตรฐานไม่มี เช่น ค่าชดเชยหัวฉีดรายสูบ อุณหภูมิน้ำมันเกียร์ เขม่าใน DPF ใช้ได้ 3 ทาง:

1. **คลังชุดข้อมูล** (มากับแอป `assets/ext_packs/` 37 ชุด) — กระบะ/PPV/รถตู้: Toyota Hilux/Fortuner, Hiace, Mitsubishi Triton/Pajero Sport,
   Ford Ranger/Everest, Chevrolet Colorado, Isuzu D-Max/MU-X (3 ช่วงปี) และรถเก๋ง/อเนกประสงค์ยอดนิยม
   (Toyota, Honda, Mazda, Nissan, MG, Mitsubishi, Suzuki, Ford) แปลงจากฐานข้อมูลเปิด OBDb
   ทุกสูตรถูกตรวจกับคำตอบจริงที่ OBDb บันทึกจากรถ (ตัวอย่างคำตอบติดไปกับค่าแต่ละตัว และมีเทสต์ตรวจซ้ำในแอป)
   ค่าที่มีคำตอบจริงขึ้นป้าย "พบในรถจริง" ที่เหลือขึ้น "รอยืนยัน" — ปุ่ม **หาชุดที่ตรงกับรถคันนี้** / **ทดสอบกับรถคันนี้**
   ถามคำสั่งตัวอย่างแล้วบอกว่ารถตอบกี่คำสั่ง
   ชุด **Isuzu D-Max (2007–2011) · เทียบกับ Tech2** วัดเองจากรถจริง (D-Max 2007 4JJ1 กล่อง 98135379) เทียบกับ Isuzu Tech2
   และ PID มาตรฐานของรถคันเดียวกัน: อุณหภูมิน้ำ/น้ำมัน/อากาศเข้า แรงดันเซนเซอร์ต่างๆ APP 1–3 ลิ้นเร่งไอดี บูสต์ที่ต้องการ
   v0.6.4 เพิ่ม 7 ค่าที่เทียบกับ PID มาตรฐานของรถคันเดียวกัน (27 ต.ค.): รอบเครื่อง 221203 (A×256+B) ความดันราง 221250 (MPa)
   และที่ยังรอยืนยัน: ความดันรางที่ต้องการ 221450 แรงดันเซนเซอร์ความดันราง 221150 ตำแหน่งคันเร่ง 221200 รอบเครื่องค่าที่ 2 221204
   รอบเดินเบาที่ต้องการ 221410 — หน้าทดสอบรีแมพจึงแสดงความดันรางจริงเทียบกับที่ต้องการของ D-Max 2007 ได้
   รูปแบบเลขของกล่องนี้: 11xx แรงดันเซนเซอร์ (V) / 12xx ค่าจริงของเซนเซอร์เดียวกัน (เลขท้ายเดียวกัน) / 14xx ค่าที่กล่องต้องการ
   รายการเลขของรุ่นอื่นในเน็ต (Colorado, BT-50/D-Max 2020+) ใช้กับกล่องนี้ไม่ได้ เลขเดียวกันเป็นคนละค่า
   (สร้างใหม่เฉพาะชุดที่เขียนเอง: `python tool/ext_packs/make_packs.py assets/ext_packs --manual-only`)
2. **เทียบกับเครื่องมือศูนย์** — หน้ารายละเอียดของแต่ละค่า: ดูไบต์สด, บันทึกจุดเทียบกับค่าที่ Techstream / G-IDSS / MUT-III แสดง,
   ให้แอปหาสูตรจากจุดเทียบ (ไบต์เดี่ยว/16 บิต/มีเครื่องหมาย × ค่าคูณ + ค่าบวก) แล้วกดยืนยัน (บันทึกชื่อร้าน วันที่ และรถ)
3. **ค้นหาค่าที่กล่องตอบ** — ไล่ถามเลขคำสั่ง 21/22 ตามช่วงของชุดในคลังหรือกำหนดเอง แล้วแตะผลเพื่อดูไบต์สดและหาสูตร
   หลังค้นหาจะสรุปแต่ละช่วง (เจอ / ปฏิเสธพร้อมรหัส / เงียบ) และบอกว่าควรลองอะไรต่อ
   ปุ่ม **บันทึกเลขที่เจอทั้งหมดเป็นชุดใหม่** เก็บทุกเลขไว้ในชุดเดียว (ชื่อรถและวันที่)
   เลขที่เจอขึ้นเป็น "ค่าใหม่ <กล่อง> <คำสั่ง>" เพราะกล่องส่งมาแค่ตัวเลข ไม่ได้บอกชื่อ
   **ตั้งชื่อจากคลัง** (v0.6.3): ถ้าเลขตรงกับค่าในชุดคลังของรถรุ่นเดียวกัน (ยี่ห้อ รุ่นตรง และปีอยู่ในช่วงปีของชุด ไม่เผื่อ ±1 ปี
   เพราะรุ่นใหม่ใช้เลขคนละชุด) หน้าชุดขึ้นการ์ด "รู้แล้วว่าเป็นค่าอะไร" กดครั้งเดียวได้ชื่อ สูตร หน่วย กลุ่ม (หน้าของแต่ละค่าก็มีปุ่ม
   "ใช้ชื่อและสูตรนี้") เช่น เลขที่ D-Max 2007 ตอบ 84 เลข ได้ชื่อจากคลัง 23 ค่า (v0.6.4) ที่เหลือใช้ข้อ 4 หรือเทียบกับเครื่องมือศูนย์
4. **จับคู่กับค่า OBD มาตรฐาน** (v0.5.2) — ใช้รถคันนั้นเองเป็นตัวเทียบแทนเครื่องมือศูนย์: อ่านค่าในชุดพร้อมค่ามาตรฐาน
   (รอบเครื่อง ความร้อนน้ำ อากาศเข้า แรงดันอากาศ ฯลฯ) ซ้ำหลายรอบขณะค่าเปลี่ยน (ติดเครื่อง เร่งเครื่องทีละระดับ ปล่อยให้เครื่องร้อน)
   แล้วหาว่าเลขไหนเปลี่ยนไปพร้อมกับค่าไหนด้วยสูตรที่ตรงทุกจุด กด "ใช้สูตรนี้" เพื่อตั้งชื่อ หน่วย สูตร และเก็บจุดเทียบเป็นหลักฐาน
   (ยังไม่ถือว่าร้านยืนยัน ต้องกดยืนยันเองในหน้ารายละเอียด)

ความปลอดภัย: ใช้เฉพาะคำสั่งอ่าน (01/21/22), ไม่ส่ง header 29 บิตบนรถ 11 บิต (และกลับกัน), จำคำสั่งที่รถไม่ตอบไว้ไม่ถามซ้ำ,
ส่งคำสั่งที่ซ้ำกันครั้งเดียวแล้วถอดหลายค่า
- ชุดที่ยี่ห้อ/รุ่น/ปี (±1 ปี) ไม่ตรงกับรถที่ต่ออยู่ แอปถามเฉพาะกล่องเลขมาตรฐานของ OBD (7DF, 7E0–7E7, 18DB33F1, 18DAxxF1)
  เพราะเลขเฉพาะยี่ห้อ (เช่น 700, 7C0) รถคนละรุ่นอาจใช้เป็นข้อความปกติ คำสั่งจะไปชนกันได้
- ค้นหา/อ่านเลขเฉพาะยี่ห้อทั้งที่ไม่รู้ว่าเป็นของรถคันนี้ แอปถามยืนยันก่อนทุกครั้ง
- หน้าค้นหาเลือกช่วงให้อัตโนมัติเฉพาะชุดของรถรุ่น/ปีนี้ ถ้าไม่มี (เช่น D-Max 2007) ใช้ช่วงทั่วไปที่ส่งไปกล่องเลขมาตรฐานเท่านั้น

ใช้กับรถจริง (สิ่งที่แอปจัดการให้):
- **รถไม่ตอบเลย** (ปิดสวิตช์กุญแจ/ตัวสแกนหลุด): แอปถาม OBD มาตรฐานซ้ำเพื่อแยกออกจาก "รถไม่รองรับคำสั่ง" แล้วขึ้นว่า "รถไม่ตอบ"
  ไม่สรุปว่าชุดไม่ตรงรุ่น ไม่จำว่าคำสั่งใช้ไม่ได้ และหยุดอ่านต่อเนื่อง/หยุดค้นหาทันที
- **คำสั่งที่เงียบ** ข้ามหลังเงียบ 2 รอบติดกัน (กันพลาดจากจังหวะที่กล่องไม่ว่างครั้งเดียว) ส่วนรหัสปฏิเสธที่ถามซ้ำก็ไม่ได้ค่า
  (ไม่รองรับ 11/12/31, ล็อกไว้ 33, ต้องเข้าโหมดพิเศษ 7E/7F) ข้ามตั้งแต่รอบถัดไป — กดเมนู ⋮ > "ลองคำสั่งที่รถไม่ตอบอีกครั้ง" เพื่อล้าง
- รหัสปฏิเสธแสดงเป็นภาษาไทย เช่น "สภาพรถยังไม่พร้อม (บางค่าต้องติดเครื่อง)" (0x22) ซึ่งแอปจะถามใหม่รอบถัดไป
- ตัวสแกนรุ่นเก่าที่ไม่รับ header 29 บิตแบบ 4 ไบต์ (ตอบ "?") แอปตั้งเป็น ATCP + 3 ไบต์ให้เอง
- จุดเทียบกับเครื่องมือศูนย์จับคู่กับไบต์ที่อ่าน "ตอนกดบันทึก" เสมอ (ถ้าไม่ได้ดูไบต์สดอยู่ แอปอ่านใหม่ก่อนบันทึก)

## ทดสอบก่อน/หลังรีแมพ (v0.6.0)

หน้าหลัก > เครื่องมือช่าง > **ทดสอบรีแมพ** — ขับทดสอบรอบ "ก่อนรีแมพ" ไว้เป็นจุดเทียบ แล้วทดสอบ "หลังรีแมพ" เส้นทางเดิม

- **ระหว่างขับ**: อ่านความเร็วและรอบเครื่องทุกรอบ ค่าอื่นสลับกันอ่าน รถ CAN ถามหลาย PID ในคำสั่งเดียว (สูงสุด 6 ตัว
  ตามมาตรฐาน ISO 15765-4) ได้อัตราสูงกว่าถามทีละตัวมาก ถ้ากล่องตอบไม่ครบ แอปกลับไปถามทีละตัวเอง
  จอแสดงความเร็ว รอบ บูสต์ (เกจ) จริง/ที่ต้องการ ความดันรางจริง/ที่ต้องการ ตัวใหญ่ พร้อมจับเวลา 0–100, 60–100, 80–120 ทันที
- **ค่าจริงเทียบค่าที่กล่องต้องการ**: PID 70 (บูสต์) และ 6D (ความดันราง) ให้ทั้งสองค่าในคำตอบเดียวกัน จึงเทียบกันได้ตรงเวลา
  รถที่ไม่มีสองตัวนี้ (เช่น D-Max 2007) ใช้ "บูสต์ที่ต้องการ" จากชุดค่าเฉพาะยี่ห้อ (7E0 22 1130) เทียบกับความดันท่อไอดี (PID 0B)
  — แอปเลือกค่าจากชุดของรถรุ่นนั้นให้เอง (ชื่อ/หน่วย: kPa, bar, psi, MPa แปลงให้)
- **แจ้งเตือนทันที** (แถบแดง สั่น และเสียงพูด): บูสต์เกินค่าที่กล่องต้องการ, บูสต์ไม่ถึง, ความดันรางต่ำ/สูงกว่าที่ต้องการ,
  เหยียบเกือบสุดแต่บูสต์ไม่ขึ้น (อาการเข้าโหมดป้องกันตัวเอง), ความร้อนน้ำ/อากาศเข้า/ไอเสียสูง, ไฟเตือนเครื่องยนต์ติดระหว่างทดสอบ
  เทียบเฉพาะช่วงที่ค่าที่ต้องการนิ่งแล้ว (ตอนเปลี่ยนเกียร์และตอนเทอร์โบกำลังปั่นจึงไม่เตือนผิด) และต้องเป็นต่อเนื่อง 1 วินาทีขึ้นไป
  เกณฑ์ความร้อนและ "บูสต์สูงสุดที่ยอมรับ" ใช้ค่าจาก ตั้งค่า > แจ้งเตือน
- **อ่านรหัสปัญหาก่อนและหลังทดสอบ** (อ่านอย่างเดียว ไม่ลบ) รหัสที่เกิดใหม่ขึ้นเป็นความเสี่ยง
- **ผล**: สรุป สิ่งที่พบพร้อมเวลา ค่าสูงสุด กราฟบูสต์/รางจริงเทียบที่ต้องการ บูสต์ตามรอบเครื่อง ส่งออก CSV และรายงาน PDF
- **เทียบก่อน/หลัง**: ตารางตัวเลข (เขียว = ดีขึ้น แดง = แย่ลง บูสต์สูงขึ้นไม่ตัดสินว่าดี), กราฟความเร็วซ้อนกันที่จุดเริ่มจับเวลา,
  บูสต์/ความดันรางสูงสุดตามรอบเครื่องแบบกราฟไดโน และรายงาน PDF เทียบก่อน/หลังพร้อมโลโก้อู่
- ผลเก็บเป็นไฟล์ JSON ในเครื่อง (`remap_runs/`) โหมดทดลองมีรถจำลองดีเซลเทอร์โบให้ลองทั้งขั้นตอน

## เสียงพูดเตือน

ค่าเกินเกณฑ์ขณะเปิดค่าสด/แดชบอร์ด/บันทึก แอปพูดภาษาไทย เช่น "ระวัง ความร้อนเครื่องสูง 108 องศา ควรจอดพักเครื่อง"
เปิดปิดและทดลองฟังที่ ตั้งค่า > แจ้งเตือนค่าผิดปกติ (ใช้เสียงอ่านข้อความของเครื่อง ต้องมีเสียงภาษาไทยของ Google TTS)
